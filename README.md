# API Key 轮询器（astrbot_plugin_key_rotator）

同一服务商的多个 API Key 轮流使用，超时、限流、鉴权失败自动换 Key，失败 Key 冷却后再回归。

**版本**：v1.0.0 ｜ **适用**：AstrBot >=4.5,<5 ｜ **依赖**：无第三方库

## 功能

- **多 Key 轮询**：同一条线路填多个 Key，按顺序循环（或随机），分摊负载、分散限流。
- **失败自动换 Key**：超时/连接失败、429 限流、鉴权失败时立刻换下一个 Key 重试，而不是同一 Key 反复重试。
- **失败冷却**：某个 Key 连续失败达到阈值后暂停参与轮换，冷却结束自动回归。
- **以新提供商类型接入**：内置 `OpenAI Compatible（多 Key 轮询）` 类型，保留原有 api_base、Key 与超时配置即可切换，不改 AstrBot 源码。
- **手动 Key 池**：某些模型的 Key 读不到时，可在面板按模型填一个或多个 Key，填 1 个固定、填多个轮换。
- **网页面板**：线路、Key 分配与成败、冷却倒计时、事件流、限速与设置都在 WebUI 里完成。
- **状态命令**：管理员发送 `/keyrot` 查看各线路 Key 的分配与冷却状态。
- **限速与兜底**：按分钟限速并均分到每个 Key；全部 Key 不可用时移交备用模型。

## 安装

把插件目录放入 `data/plugins/`，重载插件或重启 AstrBot 即可；无第三方依赖。

## 接入

安装后在 WebUI「模型提供商」里二选一：

- **方式 A（推荐）**：编辑已有服务商，把「类型」改成 `OpenAI Compatible（多 Key 轮询）`，其余配置不变，保存即生效。也可在插件面板「模型配置」里点「开启轮换」一键完成。
- **方式 B**：新增服务商，类型选 `OpenAI Compatible（多 Key 轮询）`，填写 api_base 与多个 Key，保存后再新增/编辑模型指向这条线路。

> 类型下拉里没有这一项，说明插件没加载成功，先检查启动日志。

## 配置

插件管理 → API Key 轮询器 → 配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 总开关 | 开 | 关闭后回到原生行为（全部 Key 随机取），线路配置保留 |
| 日志记录每次使用的 Key | 关 | 记录分到的 Key（脱敏），用于验证轮换 |
| 启用 /keyrot 命令 | 开 | 管理员查看状态 |
| 轮换策略 | round_robin | `round_robin` 顺序循环；`random` 随机 |
| 超时/连接失败换 Key | 开 | 关键开关：超时后立刻换下一个 Key |
| 429 限流换 Key | 开 | 限流时换到下一个 Key |
| 换 Key 重试次数 | 1 | 一次请求最多换几个 Key（不含首次），0 = 直接交给回退链 |
| 失败冷却（时长 / 连续失败阈值） | 60 秒 / 2 次 | 冷却期该 Key 不参与轮换；阈值同时是模型级熔断阈值 |
| 限速（每分钟调用数） | 0（不限速） | 按线路 Key 数均分，用满跳过，全满移交备用模型 |
| 最后兜底模型 | 空 | 追加到回退链末位，保证全部失败仍有备用 |

## 面板

入口：WebUI →「插件管理」→ API Key 轮询器 →「页面」。

- **线路概览**：每条轮询线路的模型、api_base 与「下一个轮到第几个」。
- **Key 明细**：分配次数、成功/失败、冷却倒计时与最近错误，Key 始终脱敏。
- **实时动态**：成功 / 失败 / 换 Key / 冷却事件滚动。
- **模型配置**：查看全部线路与模型，改超时、接口地址、代理，一键开启轮换，管理手动 Key 池、删除与恢复模型。
- **差异诊断**：配置类型与实际实例不一致时给出提示（如改了类型未保存、实例未重建）。

## 最坏耗时：超时 × 重试次数

三个参数分属两处配置，面板会把它们配对展示、配对修改：

| 参数 | 归属 | 说明 |
| --- | --- | --- |
| 超时时间 | AstrBot 服务商配置 | 面板可改并保存，支持单条修改或同步到全部线路 |
| 换 Key 重试次数 | 插件配置 | 一次请求最多换几个 Key（不含首次） |
| 底层请求重试次数 | AstrBot 原生「异常重试次数」 | 含首次；调到 1 才能让换 Key 尽快生效 |

全部超时且底层重试都跑完时的最坏耗时：

```text
最坏耗时 ≈ 超时 × 底层重试次数 ×（换 Key 重试次数 + 1）
```

例：超时 60 秒、底层重试 1、换 Key 1 次 → 最坏 120 秒；面板线路卡片上有实时估算。

## 指令

```text
/keyrot   （管理员）查看各线路 Key 的分配次数、成功/失败数与冷却状态
```

输出示例：

```text
## API Key 轮询状态
总开关：开启｜策略：顺序轮询｜换 Key 次数：1
### agnes-2.5-flash（线路 agens）
Key 5 个｜下一个：第 3 个
1. sk-****...8ImA  分配 12｜成功 11｜失败 1
2. sk-****...JWSB  分配 12｜成功 12｜失败 0
```

## 注意事项

- **轮换的是 Key，不是线路**：多个 Key 必须填在同一条服务商（同一个 api_base）里才会轮换；跨线路容错仍由 AstrBot「回退对话模型」负责。
- **粒度是每次 LLM 调用**：一条消息内的多轮工具调用会分别换 Key，负载更均匀。
- **流式请求一旦开始输出就不换 Key**，避免内容重复，失败仍交给回退链。
- 插件需保持启用：禁用后轮询类型无法加载，对应模型不可用；想停用轮换请用插件「总开关」。
- 面板、指令与日志只显示脱敏 Key；手动 Key 池明文保存在本机 `data/plugin_data/`，与 AstrBot 自身配置一致。
- 仅支持 OpenAI 兼容实现，Anthropic / Gemini 等不支持。
